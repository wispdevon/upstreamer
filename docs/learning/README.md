# Learning through real work

Use each development task to identify something useful to understand, practice it, and leave evidence another developer can assess.

1. Identify a learning objective tied to a real problem.
2. Plan a small agent task with acceptance criteria and verification. Reuse the accepted task plan; do not replace unfinished unrelated work.
3. Implement within the authorized scope and test the actual behavior.
4. Record what changed your understanding using the [note template](template.md). Link exact commands, revisions, outcomes, and limitations. An exercise or filled checklist never proves production readiness.
5. Update this index and assess whether a lesson, tool, or reusable agent skill should improve. Put larger opportunities in the [backlog](backlog.md).

Repository notes are reviewable Markdown files maintained by agents. The `/notes` journal is browser-local and separate: download its Markdown and give it to your agent to adapt into a repository note. There is no automatic synchronization or import.

Keep notes concise, evidence-backed, and free of secrets or private user data. Update an existing note when new evidence improves the same lesson.
